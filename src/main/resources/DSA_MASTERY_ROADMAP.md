## Week 1: Recursion Fundamentals ← Start Here

### 🧠 Why This Week Exists
Recursion is the **single most foundational skill** for DSA interviews. Trees, Graphs, Backtracking, and DP are all recursion in disguise. If your recursion is shaky, you'll hit a wall the moment you reach those topics. One week now saves two months of confusion later.

### 🧠 Concepts to Master

#### The Correct Mental Model — "Trust the Recursion"
Most beginners try to trace every recursive call in their head. That's the wrong approach and it breaks down once recursion is more than 2–3 levels deep.

The correct approach:
1. **Define the function contract precisely** — what does it return / what does it do?
2. **Assume the function works correctly for smaller inputs** — trust it
3. **Use that result** to compute the answer for the current input
4. **Identify the base case** — the smallest input where the answer is known directly

**Example — Sum of first n natural numbers:**
- Contract: `sum(n)` returns the sum `1 + 2 + ... + n`
- Base case: `sum(0) = 0` (or `sum(1) = 1`)
- Recursive case: `sum(n) = n + sum(n-1)` — trust that `sum(n-1)` gives you the correct sub-sum

The moment you define the contract precisely, the recursive case often becomes obvious.

#### The Call Stack — What Actually Happens in Memory
- Every function call creates a **stack frame** on the call stack containing: local variables, parameters, return address
- Stack frames are pushed when a function is called and popped when it returns
- **Stack overflow** occurs when recursion is too deep (JVM default stack ≈ 512 calls to several thousand depending on frame size)
- **Space complexity of recursion = depth of the call stack** = O(depth)
- Draw the call stack for small examples until you internalize this

#### Recursion Tree — How to Analyze Time Complexity
- Draw a tree where each node = one function call
- **Total number of nodes = total number of function calls = time complexity** (if each call does O(1) work)
- **Number of levels = recursion depth**

**Fibonacci analysis (naive):**
```
fib(4)
├── fib(3)
│   ├── fib(2) → fib(1) + fib(0)
│   └── fib(1)
└── fib(2)
    ├── fib(1)
    └── fib(0)
```
- Height = n, branching factor = 2 → O(2^n) nodes → O(2^n) time
- With memoization: each unique subproblem computed once → O(n) time

**Merge Sort analysis:**
- T(n) = 2T(n/2) + O(n)  ← Master Theorem
- Height = log(n), each level does O(n) total work → O(n log n)

#### Four Types of Recursion You Must Know

**1. Linear Recursion — one recursive call:**
```java
int factorial(int n) {
    if (n == 0) return 1;          // base case
    return n * factorial(n - 1);  // one call, shrinks by 1 each time
}
```
Time: O(n), Space: O(n) call stack

**2. Binary Recursion — two recursive calls:**
```java
int fib(int n) {
    if (n <= 1) return n;
    return fib(n-1) + fib(n-2);  // two calls
}
```
Time: O(2^n) without memo, O(n) with memo. Space: O(n) stack depth

**3. Tail Recursion — recursive call is the last operation:**
```java
int factorial(int n, int acc) {
    if (n == 0) return acc;
    return factorial(n-1, n * acc);  // tail call — no work after this returns
}
```
JVM doesn't optimize tail calls by default, but the concept is important. Tail recursion can always be converted to an iterative loop.

**4. Mutual Recursion — two functions calling each other:**
```java
boolean isEven(int n) { return n == 0 ? true : isOdd(n-1); }
boolean isOdd(int n)  { return n == 0 ? false : isEven(n-1); }
```

#### Tower of Hanoi — The Classic Recursion Problem
You MUST understand this completely. It's the canonical example of recursion that doesn't have an obvious iterative equivalent.

**Problem:** Move n disks from `src` peg to `dst` peg using `aux` peg. Rule: never place a larger disk on a smaller one.

**Key insight:** To move n disks from src to dst:
1. Move top `n-1` disks from `src` to `aux` (using `dst` as helper)
2. Move the largest disk from `src` to `dst`
3. Move `n-1` disks from `aux` to `dst` (using `src` as helper)

```java
void hanoi(int n, char src, char dst, char aux) {
    if (n == 1) {
        System.out.println("Move disk 1 from " + src + " to " + dst);
        return;
    }
    hanoi(n-1, src, aux, dst);   // move n-1 disks to aux
    System.out.println("Move disk " + n + " from " + src + " to " + dst);
    hanoi(n-1, aux, dst, src);   // move n-1 disks from aux to dst
}
```

Recursion tree: binary tree with height n → **2^n - 1 total moves** (minimum possible)
Time: O(2^n), Space: O(n) — the depth of the call stack
- **Watch:** [Abdul Bari — Tower of Hanoi](https://www.youtube.com/watch?v=q6RicK1FCUs)

#### Backtracking Preview — Recursion with Undo
You'll study this deeply in Week 13–14, but understand the idea now:
- Make a choice → recurse → **undo the choice** (backtrack)
- This explores all possible paths in the state space tree
- Every backtracking problem is recursion + an undo step

```java
// Generate all binary strings of length n — preview of backtracking
void generate(char[] arr, int pos) {
    if (pos == arr.length) {
        System.out.println(new String(arr));
        return;
    }
    arr[pos] = '0';
    generate(arr, pos + 1);   // recurse with '0'
    arr[pos] = '1';
    generate(arr, pos + 1);  // recurse with '1'
    // no explicit "undo" needed here since we overwrite arr[pos]
}
```

#### Recursion vs Iteration — When to Choose Which
- **Use recursion when:** The problem structure is naturally recursive (trees, divide-and-conquer, backtracking), recursive code is clearer
- **Use iteration when:** Stack overflow is a risk (very large n), performance is critical (no function call overhead), the recursion is tail-recursive (trivially convert to loop)
- **Convert to iteration when asked:** Use an explicit stack to simulate the call stack

## Week 2–3: Arrays & Hashing

### 🧠 Concepts to Master

#### Time & Space Complexity — Study This Before Any Problem
Understanding complexity is the prerequisite for everything else. You need to be able to analyze any algorithm on the fly.

- **Big-O notation:** Describes the **upper bound** of an algorithm's growth rate as input size grows. O(n) means linear, O(n²) means quadratic, O(log n) means logarithmic.
- **Why it matters in interviews:** Every solution you give must come with a time and space complexity analysis. Any interviewer at a product company expects this automatically.
- **Best / Average / Worst case:** QuickSort is O(n log n) average but O(n²) worst case. Know when each applies.
- **Amortized analysis:** ArrayList's `add()` is O(1) amortized — most inserts are O(1), but occasionally one causes a resize (O(n)). The cost is spread over all operations.
- **Space complexity:** Count both auxiliary space (extra memory you use) and call stack space in recursive solutions.
- **Common complexities ranked (fast to slow):** O(1) → O(log n) → O(n) → O(n log n) → O(n²) → O(2^n) → O(n!)
- **Watch first:** [Abdul Bari — Time Complexity Playlist](https://www.youtube.com/playlist?list=PLDN4rrl48XKpZkf03iYFl-O29szjTrs_O)

#### Two Pointers Technique
A pattern where two index variables scan through the array, often from both ends or in the same direction at different speeds.

- **When to apply:** Sorted arrays, pair/triplet sum problems, palindrome checks, partition problems
- **Both-ends variant:** Start left=0, right=n-1. Move based on comparison:
  - `arr[left] + arr[right] < target` → move left right (increase sum)
  - `arr[left] + arr[right] > target` → move right left (decrease sum)
- **Same-direction variant:** Slow pointer tracks "write position" while fast pointer reads. Used for removing duplicates in-place.
- **Mental model:** Two pointers collapse the search space without nested loops, reducing O(n²) brute force to O(n).

#### Prefix Sum
Precompute cumulative sums so any range query is answered in O(1) instead of O(n).

- **Build:** `prefix[0] = arr[0]`, then `prefix[i] = prefix[i-1] + arr[i]`
- **Range query:** `sum(l, r) = prefix[r] - prefix[l-1]` (handle l=0 as edge case)
- **When to apply:** "Subarray sum equals k", range sum queries, "sum divisible by k"
- **Prefix sum + HashMap trick:** Store `prefix[i] % k` in a map to find subarrays whose sum is divisible by k in O(n)
- **2D prefix sums:** Extend the same idea to matrices for rectangular range sum queries

#### Hashing
Trade space for time — get O(1) average lookup instead of O(n) search.

- **Complement pattern (Two Sum):** For each `nums[i]`, check if `target - nums[i]` exists in the map. If not, store `nums[i]` in the map.
- **Frequency map:** `map.put(x, map.getOrDefault(x, 0) + 1)` — count occurrences of every element
- **Grouping by computed key:** Group anagrams by their sorted string. Group by character frequency array.
- **Java HashMap internals you should know:** Backed by array of linked lists (or trees for Java 8+). `hashCode()` determines bucket. `equals()` resolves collision. Average O(1), worst case O(n) with all collisions.
- **HashSet vs HashMap:** Use HashSet when you only need existence check; HashMap when you need key→value mapping

#### Kadane's Algorithm — Maximum Subarray Sum
Finds the maximum sum of any contiguous subarray in O(n) time, O(1) space.

- **Core idea:** At each position, ask: "Is it better to extend the previous subarray or start fresh here?"
- **Recurrence:** `currentMax = max(nums[i], currentMax + nums[i])`
- **Update global:** `globalMax = max(globalMax, currentMax)`
- **Why reset to nums[i]?** If `currentMax + nums[i] < nums[i]`, the previous subarray hurts us — it's better to start fresh. This happens when `currentMax < 0`.
- **Variation:** Track start/end indices if you need to print the actual subarray

#### Dutch National Flag Algorithm — 3-Way Partition
Sorts an array of 3 distinct values (0s, 1s, 2s) in O(n) time, O(1) space. Single pass.

- **Three pointers:** `low` (boundary for 0s), `mid` (current element), `high` (boundary for 2s)
- **Invariants maintained throughout:**
  - `arr[0..low-1]` → all 0s
  - `arr[low..mid-1]` → all 1s
  - `arr[high+1..n-1]` → all 2s
  - `arr[mid..high]` → unseen/unexplored region
- **Rules:**
  - `arr[mid] == 0` → swap(mid, low), low++, mid++
  - `arr[mid] == 1` → mid++ (already in correct region)
  - `arr[mid] == 2` → swap(mid, high), high-- (don't move mid — newly swapped element unseen)
- **Generalization:** Any 3-way partition (e.g., partition around a pivot in QuickSort)

#### Boyer-Moore Voting Algorithm — Majority Element
Finds an element appearing more than n/2 times in O(n) time, O(1) space.

- **Algorithm:** Maintain `candidate` and `count`. If `count == 0`, reset candidate to current element. If current == candidate, increment count. Else decrement count.
- **Intuition:** Every non-majority element cancels one occurrence of the majority element. Since majority appears >n/2 times, it has enough to survive all cancellations.
- **Must verify:** The algorithm finds a *candidate*, not a *guarantee*. If you're not sure a majority exists, do a second pass to verify the count.
- **Extension to n/3:** Use two candidates. At most 2 elements can appear >n/3 times.

#### Sorting Algorithms — Theory (Abdul Bari Deep Dives)
You must understand these from internals, not just call `Arrays.sort()`.

- **Merge Sort:** Divide array in half, sort each half, merge. Always O(n log n). Stable. Requires O(n) extra space. Best for linked lists and external sorting.
- **Quick Sort:** Pick a pivot, partition so elements < pivot are left, > pivot are right. Recurse on both halves. Average O(n log n), worst O(n²) on sorted input with bad pivot. In-place (O(log n) stack). Fastest in practice for random data.
- **Heap Sort:** Build max-heap (O(n)), repeatedly extract max (O(log n) × n). O(n log n) always. In-place. Not stable. Good when guaranteed O(n log n) needed with O(1) space.
- **Java's under the hood:** `Arrays.sort()` for primitive types → Dual-Pivot QuickSort. For objects → TimSort (a hybrid of merge sort + insertion sort). TimSort is stable, O(n log n) worst case.

## Week 4–5: Strings + Sliding Window

### 🧠 Concepts to Master

#### Sliding Window — The Most Versatile Pattern
A technique that maintains a "window" (contiguous subarray/substring) and slides it across the data without restarting computation from scratch each time.

**Fixed-size window (window size k given):**
- Compute initial window, then slide: add the new right element, remove the old left element
- O(n) total — you process each element exactly twice
- Use for: max sum subarray of size k, find all anagrams of pattern in string

**Variable-size window (expand and shrink based on condition):**
- Expand right pointer when window is valid or hasn't satisfied condition yet
- Shrink left pointer when window becomes invalid (violates constraint)
- **Key invariant:** Right pointer never goes backward. The window always moves right.
- O(n) because each element enters the window once and leaves once — O(2n) total
- Use for: longest substring without repeating characters, minimum window substring, longest repeating character replacement

**Variable-window template:**
```
left = 0
windowState = {}   // HashMap, count, etc.

for right in range(len(s)):
    // 1. Add s[right] to window state
    windowState.update(s[right])

    // 2. Shrink left when window is invalid
    while (window is invalid / violates constraint):
        windowState.remove(s[left])
        left += 1

    // 3. Update answer — current window [left..right] is valid
    answer = max(answer, right - left + 1)
```

#### KMP Algorithm — String Matching in O(n+m)
The naive string search is O(n×m). KMP exploits the pattern's self-similarity to skip redundant comparisons.

- **LPS array (Longest Proper Prefix which is also a Suffix):**
  - `lps[i]` = length of the longest proper prefix of `pattern[0..i]` that is also a suffix
  - Example: pattern = "AABAAB" → lps = [0, 1, 0, 1, 2, 3]
  - Build in O(m) using two pointers on the pattern itself
- **Using LPS in search:** On a mismatch at pattern index `j` and text index `i`, don't start over.  Instead, jump to `lps[j-1]` for the next comparison in pattern, while `i` stays put.
- **Why it works:** LPS tells you the longest suffix of the partial match that could be a valid prefix — so you skip the redundant part.
- **When to use it:** Any problem requiring substring search, repeated pattern detection, finding period of a string
- **Watch:** [Abdul Bari — KMP Algorithm](https://www.youtube.com/watch?v=V5-7GzOfADQ)

#### Character Frequency Maps
- For lowercase letters only: `int[26]` is faster than HashMap (array indexing vs hash computation)
- `freq[c - 'a']++` to count, `freq[c - 'a']--` to remove
- **Anagram detection:** Two strings are anagrams iff their frequency arrays are identical — compare in O(26) = O(1)
- **Sliding window + frequency:** Use a `matches` counter. Track how many of the target characters are fully satisfied. When `matches == distinctCharsInTarget`, window is valid.

#### Expand Around Center — Palindrome Finding
- For each index `i`, expand outward while `s[left] == s[right]`
- Two cases: odd-length palindrome (center at `i`) and even-length palindrome (center between `i` and `i+1`)
- O(n²) time overall — better than naive O(n³), but Manacher's gives O(n) if needed

### 🧠 Concepts to Master — Linked Lists

#### Pointer Manipulation — The Core Skill
Everything in linked lists comes down to correctly managing pointers. Before writing a single line of code, draw the nodes and arrows.

- **Three-pointer reversal (in-place):**
  - `prev = null`, `curr = head`, `next = null`
  - Loop: `next = curr.next` → `curr.next = prev` → `prev = curr` → `curr = next`
  - After loop: `prev` is the new head
  - **Most common mistake:** Losing access to the rest of the list by setting `curr.next` before saving `next`

- **Dummy node pattern:** Create a fake node before the actual list head
  - `dummy.next = head`; return `dummy.next` at the end
  - Eliminates special cases for operations at the head (no null checks needed)
  - **Always use for:** Merge two lists, remove specific node, add two numbers, any problem where head might change

#### Fast & Slow Pointer — Floyd's Algorithm
Two pointers moving at different speeds. One of the most elegant ideas in CS.

- **Cycle detection:** Fast moves 2 steps each iteration, slow moves 1 step
  - If they ever meet → cycle exists
  - If fast reaches null → no cycle
- **Finding cycle entry point:** After fast and slow meet inside the cycle:
  - Reset slow to head. Keep fast at meeting point.
  - Move both 1 step at a time. They meet at the cycle's entry node.
  - **Why?** Mathematical proof: distance from head to entry = distance from meeting point to entry (modular arithmetic over cycle length)
- **Finding middle of list:** When fast reaches the end (null or last node), slow is at the middle
- **Finding nth from end:** Move fast N steps ahead. Then move both 1 step. When fast hits end, slow is N from end.

#### Merge Pattern
- Compare heads of two sorted lists. Pick the smaller head as the next node.
- Use a dummy node to avoid edge cases on the first merge step.
- This is the foundation of Merge Sort on Linked Lists and the Merge K Sorted Lists heap approach.

#### LRU Cache — The Most Important Linked List Design Problem
Combines Doubly Linked List + HashMap for O(1) get and O(1) put.

- **DLL maintains access order:** Most recently accessed/inserted at head. Least recently used at tail.
- **HashMap provides O(1) lookup:** key → node in DLL
- **get(key):** If key exists in map, move node to head (it's now most recently used), return value. Else return -1.
- **put(key, value):** If key exists, update value and move to head. If new key: create node at head, add to map. If over capacity: remove tail node, delete from map.
- **Four helper operations:** `addToHead(node)`, `removeNode(node)`, `removeTail()`, `moveToHead(node)`

### 🧠 Concepts to Master — Stacks & Queues

#### Monotonic Stack
A stack that maintains its elements in strictly increasing or decreasing order. When you push a new element, pop everything that violates the monotonic property first.

- **Monotonically decreasing stack (for Next Greater Element):**
  - While stack top < current element: pop it (current element is the answer for it)
  - Push current element
  - Elements that were never popped have no greater element to their right
- **Monotonically increasing stack (for Next Smaller Element):** Same idea, reversed condition
- **Largest Rectangle in Histogram:**
  - Maintain an increasing stack of (index, height) pairs
  - When a shorter bar is encountered, pop all taller bars and compute their rectangle using the current index as right boundary
  - After the loop, pop remaining bars using n as right boundary
- **Trapping Rain Water:**
  - Water at each position = min(maxLeft, maxRight) - height[i]
  - Stack approach: maintain stack of indices, when taller bar found, water fills between the popped bar and the new taller bar

#### Monotonic Deque (for Sliding Window Maximum)
Deque (double-ended queue) maintains indices in decreasing order of values.
- **Remove from front:** If front index is outside the window (index < left), remove it
- **Remove from back:** If current element ≥ element at back index, pop back (back index can never be maximum anymore)
- **The front always holds the index of the current window's maximum**

#### Stack for Balanced Brackets
When you see an opening bracket, push it. When you see a closing bracket, check if stack top matches. If not → invalid. Empty stack at end = valid.

### 🧠 Concepts to Master — Recursion

#### The Right Way to Think About Recursion
Don't trace through all recursive calls. Instead:
1. **Assume the function works correctly for smaller inputs** (trust it)
2. **Define clearly what the function returns/does**
3. **Write the base case** (smallest valid input with known answer)
4. **Use the recursive result** to build the answer for the current input

This "trust the recursion" approach is how you write clean recursive tree and graph solutions later.

#### Recursion Tree & Complexity
- Drawing the recursion tree is how you analyze time complexity of recursive algorithms
- Number of nodes in the tree = number of function calls = time complexity (if each call does O(1) work)
- **Depth of tree** = space complexity (stack frames)
- **Fibonacci recursion:** Binary tree with height n → O(2^n) calls. With memoization → O(n).
- **Merge Sort recursion:** Binary tree with height log(n), each level does O(n) work → O(n log n)

#### Tower of Hanoi — Must Understand
The classic recursion problem. Know it inside-out.
- Move n disks from source to destination using auxiliary peg
- `hanoi(n, src, dst, aux)`:
  - Move top n-1 disks from src to aux (using dst)
  - Move disk n from src to dst
  - Move n-1 disks from aux to dst (using src)
- Time complexity: O(2^n) — minimum 2^n - 1 moves needed
- **Watch:** [Abdul Bari — Tower of Hanoi](https://www.youtube.com/watch?v=q6RicK1FCUs)

## Week 8–9: Binary Search

### 🧠 Concepts to Master

#### The Fundamental Idea
Binary search works when there is a **monotonic condition** — some property that is false for all values below a threshold and true for all values above it (or vice versa). At each step you eliminate half the remaining search space based on whether the midpoint satisfies the condition.

**The key insight:** You don't need an array to apply binary search. You need a **monotonic condition** and a **bounded search space**. This unlocks its power for "binary search on answer" problems.

#### Integer Overflow — Always Use This
```java
int mid = left + (right - left) / 2;  // CORRECT
int mid = (left + right) / 2;          // WRONG — can overflow when left+right > Integer.MAX_VALUE
```

#### Template 1 — Classic (Find Exact Target)
```
left = 0, right = n - 1
while left <= right:
    mid = left + (right - left) / 2
    if arr[mid] == target: return mid
    elif arr[mid] < target: left = mid + 1
    else: right = mid - 1
return -1
```
- Use `<=` in while condition (both pointers can be at same position)
- After loop, search space is empty — target not found

#### Template 2 — Find First True (Leftmost Position)
When you want the leftmost index where a condition becomes true:
```
left = 0, right = n    // right = n because answer might be n (no valid index)
while left < right:    // stops when left == right (converged)
    mid = left + (right - left) / 2
    if condition(mid): right = mid      // mid could be the answer, don't exclude it
    else: left = mid + 1
return left            // left == right == answer
```

#### Template 3 — Binary Search on Answer (Most Powerful)
When the problem asks for the **minimum/maximum value** satisfying a condition, not an index:
- Define a function `canAchieve(x)` that returns true/false
- `canAchieve` must be monotonic (e.g., if x works, x+1 also works — or vice versa)
- Binary search over the answer space, not array indices

```
left = minPossibleAnswer, right = maxPossibleAnswer
while left < right:
    mid = left + (right - left) / 2
    if canAchieve(mid): right = mid      // looking for minimum that satisfies
    else: left = mid + 1
return left
```

**Examples where this applies:**
- Koko Eating Bananas: "What is the MINIMUM eating speed that finishes in H hours?"
- Aggressive Cows: "What is the MAXIMUM minimum distance between cows?"
- Split Array Largest Sum: "What is the MINIMUM possible largest sum when split into K subarrays?"

#### Rotated Sorted Array — Key Insight
Even after rotation, one half of the array is always fully sorted.
- `arr[left] <= arr[mid]` → left half is sorted
- Otherwise → right half is sorted
- Check if target lies in the sorted half; if yes, search there; otherwise search the other half

## Week 10–11: Trees (Binary Trees + BST)

### 🧠 Concepts to Master

#### The Four Traversals — Master All Variants
| Traversal | Order | Use Case |
|---|---|---|
| Inorder | Left → Root → Right | BST gives sorted output. Find kth smallest. Validate BST. |
| Preorder | Root → Left → Right | Serialize tree. Clone tree. Build tree from traversal. |
| Postorder | Left → Right → Root | Delete tree. Evaluate expression tree. Tree DP (need children before parent). |
| Level Order (BFS) | Level by level | Right side view. Zigzag. Max width. Connect level nodes. |

**Implement BOTH recursive and iterative versions** — interviewers often ask for the iterative version specifically.

- **Iterative Inorder:** Use explicit stack. Push all left children, process top, then go right.
- **Iterative Preorder:** Push right child first, then left (so left is processed first from stack top).
- **Iterative Postorder:** Two-stack method, or reverse of modified preorder.
- **Level Order:** Use Queue. After processing a node, enqueue its left and right children.

#### Thinking Recursively About Trees — The Most Important Skill
For any tree problem, define your function contract precisely:
- What does it return for a null node?
- What does it return for a leaf node?
- How do I use the results from left and right subtrees to compute the answer for the current root?

**Template for most DFS tree problems:**
```
function dfs(node):
    if node is null: return BASE_CASE

    leftResult = dfs(node.left)
    rightResult = dfs(node.right)

    // Combine leftResult, rightResult, and node.val to compute:
    // 1. The answer contribution from this subtree
    // 2. The value to return to the parent
    return COMPUTED_VALUE
```

#### Tree DP Pattern — Return Multiple Values
Many hard tree problems need you to return multiple values up the recursion:
- **Diameter of Binary Tree:** Each call returns `(diameter_in_subtree, height_of_subtree)`. Diameter through current node = `leftHeight + rightHeight`. Return `max(leftDiam, rightDiam, leftH + rightH)` as diameter.
- **Balanced Binary Tree:** Return height if balanced, -1 if not. Parent treats -1 as "already unbalanced — propagate up."
- **Maximum Path Sum:** Each call returns the max sum of a path going DOWN from current node (can only extend one side). Update a global max with `left+ + node.val + right+` (where `x+ = max(x, 0)`).

#### BST-Specific Properties (Know These Cold)
- All nodes in left subtree < current node. All in right subtree > current node.
- **Inorder traversal of BST = sorted sequence** — this is the key to 90% of BST problems.
- **Search:** Start at root, go left if target < root, right if target > root. O(h).
- **Predecessor:** Rightmost node of left subtree. OR, first ancestor for which current node is in right subtree.
- **Successor:** Leftmost node of right subtree. OR, first ancestor for which current node is in left subtree.
- **LCA in BST:** If both p and q are less than root → LCA in left. Both greater → right. Otherwise root is LCA.
- **Validate BST:** Pass (min, max) bounds down. At each node, check `min < node.val < max`.

#### Morris Traversal — O(1) Space Inorder
Traverse a binary tree without stack or recursion using O(1) space by temporarily threading the tree.
- For each node: if it has no left child, process it and go right
- If it has a left child, find the inorder predecessor (rightmost of left subtree)
  - If predecessor's right is null → thread it to current node, go left
  - If predecessor's right is current node → unthread (restore), process current, go right
- Watch: [Striver — Morris Traversal](https://www.youtube.com/watch?v=80Zug6D1_r4)

## Week 12–13: Graphs

### 🧠 Concepts to Master

> ⚡ This is Abdul Bari's strongest section in the entire DSA curriculum. Watch every single graph video before writing code.

#### Graph Representations
- **Adjacency List:** `List<List<Integer>> adj`. O(V+E) space. Standard for most problems. Efficient for sparse graphs.
- **Adjacency Matrix:** `int[][] matrix`. O(V²) space. O(1) edge lookup. Good for dense graphs.
- **Edge List:** `int[][] edges`. Used in Kruskal's, Bellman-Ford — algorithms that process edges directly.
- In Java: most LC graph problems give you an adjacency list or edge list. Build your own adjacency list from it.

#### BFS (Breadth First Search)
Explores the graph level by level using a queue.

- **Template:**
  ```
  Queue<Integer> queue = new LinkedList<>();
  boolean[] visited = new boolean[n];
  queue.offer(start);
  visited[start] = true;
  while (!queue.isEmpty()):
      int node = queue.poll();
      // process node
      for (int neighbor : adj.get(node)):
          if (!visited[neighbor]):
              visited[neighbor] = true;
              queue.offer(neighbor);
  ```
- **When to use:**
  - Shortest path in unweighted graph (BFS level = shortest distance)
  - Level-by-level processing
  - Multi-source BFS: add ALL source nodes to queue before starting (Rotting Oranges, Pacific Atlantic)
- **BFS = shortest path.** This is the most important property. For any unweighted graph "minimum steps" problem → BFS.

#### DFS (Depth First Search)
Goes as deep as possible along a path before backtracking.

- **Template (recursive):**
  ```
  void dfs(int node, boolean[] visited, List<List<Integer>> adj):
      visited[node] = true;
      // process node
      for (int neighbor : adj.get(node)):
          if (!visited[neighbor]):
              dfs(neighbor, visited, adj);
  ```
- **3-color DFS for directed graphs (cycle detection):**
  - WHITE (0) = unvisited, GRAY (1) = currently in stack, BLACK (2) = fully processed
  - Back edge (visiting a GRAY node) = cycle

#### Topological Sort — Two Methods
Only valid for **Directed Acyclic Graphs (DAGs)**. Gives a linear ordering where for every directed edge `u→v`, `u` appears before `v`.

**Method 1 — DFS + Stack (Post-order):**
- Run DFS. When a node has fully processed (all neighbors done), push it to a stack.
- Reverse the stack = topological order.
- A back edge during DFS = cycle (use 3-color method to detect).

**Method 2 — Kahn's Algorithm (BFS + in-degree):**
- Compute in-degree (number of incoming edges) for every node.
- Add all nodes with in-degree 0 to a queue.
- While queue not empty: pop a node, add to result. For each of its neighbors, decrease in-degree by 1. If neighbor's in-degree becomes 0, add to queue.
- **If total processed == V → valid topological order. If < V → graph has a cycle.**
- This method naturally detects cycles and is easier to code correctly under interview pressure.

#### Union-Find (Disjoint Set Union — DSU)
Tracks which elements belong to the same connected component.

- **find(x):** Returns the root (representative) of x's set.
- **union(x, y):** Merges the sets containing x and y.
- **Path Compression** (optimization for `find`): After finding the root, make every node on the path point directly to the root. Flattens the tree dramatically.
  ```
  int find(int x):
      if parent[x] != x: parent[x] = find(parent[x])  // path compression
      return parent[x]
  ```
- **Union by Rank** (optimization for `union`): Always attach the smaller tree under the larger. Keeps the tree flat.
  ```
  void union(int x, int y):
      int rootX = find(x), rootY = find(y)
      if rootX == rootY: return  // already same set
      if rank[rootX] < rank[rootY]: swap(rootX, rootY)
      parent[rootY] = rootX
      if rank[rootX] == rank[rootY]: rank[rootX]++
  ```
- With both optimizations: nearly O(1) per operation (inverse Ackermann function α(n)).
- **When to use:** Undirected graph cycle detection, connected components, Kruskal's MST, any problem about merging groups.

#### Dijkstra's Algorithm — Single Source Shortest Path (Non-negative Weights)
Finds the shortest distance from a source node to all other nodes, when all edge weights are non-negative.

- **Uses a Min-Heap (Priority Queue).** Always process the closest unvisited node next.
- **Algorithm:**
  1. `dist[src] = 0`, all others = ∞. Push `(0, src)` to min-heap.
  2. Pop `(distance, node)`. If `distance > dist[node]`, skip (stale entry).
  3. For each neighbor: `if dist[node] + weight < dist[neighbor]`: update `dist[neighbor]`, push to heap.
- **Time:** O((V + E) log V) with binary min-heap.
- **Does NOT work** with negative edge weights — use Bellman-Ford instead.

#### Bellman-Ford Algorithm — Handles Negative Weights
- Relaxes all edges **V-1 times**.
- `for V-1 iterations: for each edge (u,v,w): if dist[u] + w < dist[v]: dist[v] = dist[u] + w`
- After V-1 iterations, if any edge can still be relaxed → **negative weight cycle exists**.
- **Time:** O(V × E) — slower than Dijkstra but handles negative weights.
- **When to use:** Negative edge weights, detecting negative cycles, constraint: "at most K steps" (run K iterations of relaxation).

## Week 14–15: Greedy + Heaps + Backtracking

### 🧠 Concepts to Master — Greedy

#### When Greedy Works
A greedy algorithm makes the **locally optimal choice** at each step, hoping to arrive at a globally optimal solution. It doesn't explore alternatives — it commits.

**Greedy works when:**
1. The problem has **optimal substructure** (optimal solution can be built from optimal solutions to subproblems)
2. The **greedy choice property** holds (the locally optimal choice is always part of some globally optimal solution)

**How to prove greedy is correct:** The **exchange argument**. Take any optimal solution. Show that you can swap elements to match the greedy order without making the solution worse. Therefore, the greedy order IS optimal.

**Greedy vs DP:** If you can make a local decision without reconsidering it later → greedy. If you need to explore multiple choices and the optimal depends on future choices → DP.

#### Interval Greedy Problems (Very Frequently Asked)
- **Activity Selection / Non-overlapping intervals:** Sort intervals by **end time**. Greedily always pick the interval with the earliest end time that doesn't conflict with the last selected. This maximizes the number of non-overlapping intervals.
- **Why sort by end time?** Choosing the interval that ends earliest leaves the maximum room for future intervals.
- **Meeting Rooms II (minimum rooms needed):** Sort by start time. Use a min-heap of end times. When starting a new meeting, check if the earliest-ending room is free (pop if `endTime ≤ newStart`, push new end). Heap size at any point = rooms in use.

#### Jump Game — Greedy Reach
- Track `maxReach`: the farthest index you can reach from any position explored so far
- For each index i: if `i > maxReach` → you're stuck, return false
- Update: `maxReach = max(maxReach, i + nums[i])`
- No explicit "jumps" counted — just a continuously updated frontier

### 🧠 Concepts to Master — Heaps

#### Heap Internals
- **Min-Heap:** Every parent ≤ its children. Root = minimum element. Java's `PriorityQueue` is a min-heap by default.
- **Max-Heap:** Every parent ≥ its children. In Java: `new PriorityQueue<>(Collections.reverseOrder())` or `(a, b) -> b - a`.
- **Operations:** `peek()` = O(1), `poll()` = O(log n), `offer()` = O(log n), `heapify` from array = O(n).
- **Heapify is O(n) not O(n log n):** Building a heap by inserting one at a time is O(n log n), but heapifying an entire array bottom-up is O(n). Know why.

#### Two-Heap Pattern — Dynamic Median
- Maintain two heaps: `maxHeap` for the **lower half** of elements, `minHeap` for the **upper half**
- **Invariant:** `maxHeap.size() == minHeap.size()` OR `maxHeap.size() == minHeap.size() + 1`
- **Invariant:** `maxHeap.peek() ≤ minHeap.peek()` (all lower-half elements ≤ all upper-half elements)
- **After each insertion:** Balance if sizes differ by more than 1 (transfer top of larger to smaller)
- **Median:** If equal size → average of both tops. If maxHeap larger → its top.

#### Top-K Pattern
- Use a **min-heap of size K** to maintain K largest elements
- For each new element: if it's larger than `heap.peek()`, replace it (pop and push)
- After processing all elements: heap contains the K largest. Heap top = Kth largest.
- O(n log k) — significantly better than O(n log n) sorting when k << n

### 🧠 Concepts to Master — Backtracking

#### What Backtracking Is
Backtracking is a **systematic exploration of all possibilities** with **pruning**. It's a refined brute force where you stop exploring a path as soon as you know it can't lead to a valid solution.

- **State space tree:** Each node = a partial solution state. Each edge = a choice made. Leaf = complete solution or dead end.
- **Backtracking = DFS on this state space tree + pruning branches early**

#### The Backtracking Template (Memorize This Pattern)
```
void backtrack(List<Integer> current, int start, int[] nums):
    // Base case: current state is a valid/complete solution
    if (isComplete(current)):
        result.add(new ArrayList<>(current))  // COPY — don't add reference
        return

    for (int i = start; i < nums.length; i++):
        // Pruning: skip invalid choices
        if (i > start && nums[i] == nums[i-1]): continue  // skip duplicates at same level

        current.add(nums[i])          // MAKE choice
        backtrack(current, i + 1, nums)  // RECURSE (i+1 for no reuse, i for reuse)
        current.remove(current.size() - 1)  // UNDO choice (backtrack)
```

#### Key Backtracking Concepts
- **Include/Exclude:** At each element, decide to include or exclude it. Generates all 2^n subsets.
- **Start index:** Prevents reusing elements and avoids re-examining elements from before the current position.
  - Pass `i+1` when each element can be used at most once
  - Pass `i` when elements can be reused (Combination Sum)
- **Duplicate handling:** Sort input first. Skip `nums[i] == nums[i-1]` when `i > start` (at the same recursion level).
- **N-Queens constraint checking:** For placing a queen at (row, col), check: no queen in same column, no queen on either diagonal.

## Week 16–19: Dynamic Programming

### 🧠 Concepts to Master

> ⚡ Watch **every** Abdul Bari DP video before touching problems. Then follow Striver's complete [DP playlist (50+ videos)](https://www.youtube.com/playlist?list=PLgUwDviBIf0qUlt5H_kiKYaNSqJ81PMMY) — the most structured DP series available anywhere.

#### What Is DP and When Does It Apply?
- **Overlapping subproblems:** The same subproblem appears multiple times in the recursion tree. Without memoization, you recompute it each time.
- **Optimal substructure:** The optimal solution to the main problem can be constructed from optimal solutions to its subproblems.
- If both conditions hold → DP applies.

#### Top-Down (Memoization) vs Bottom-Up (Tabulation)

**Top-Down (Memoization):**
- Write the natural recursive solution first
- Add a `memo` array — check it before computing, store result after computing
- **Advantage:** Only computes needed subproblems. Easier to derive from recursion.
- **Disadvantage:** Recursion overhead. Risk of stack overflow for very deep recursion.

**Bottom-Up (Tabulation):**
- Fill a DP table iteratively, starting from base cases
- No recursion — no stack overflow
- **Advantage:** Faster in practice. Easier to optimize space.
- **Space optimization:** If `dp[i]` only depends on `dp[i-1]` and `dp[i-2]` → use two variables, not an array. If a 2D table only needs the previous row → use 1D array.

#### The 4-Step DP Framework
1. **Define the state:** What does `dp[i]` (or `dp[i][j]`) represent? Be precise.
2. **Write the transition (recurrence):** How does `dp[i]` relate to previous states?
3. **Identify base cases:** What are the values for the smallest/simplest inputs?
4. **Determine traversal order:** Which cells must be computed before others?

#### 1D DP Patterns
- **Fibonacci-type:** `dp[i] = dp[i-1] + dp[i-2]`. Climbing Stairs, Tribonacci.
- **House Robber-type:** `dp[i] = max(dp[i-1], dp[i-2] + nums[i])`. Can't take adjacent elements.
- **Linear scan with decision:** Decode Ways — at each position, check 1-digit and 2-digit options.

#### 0/1 Knapsack — The Foundation Pattern
Decide whether to include or exclude each item. Each item usable AT MOST ONCE.
- **State:** `dp[i][w]` = maximum value using first `i` items with weight capacity `w`
- **Transition:**
  - `dp[i][w] = dp[i-1][w]` (don't take item i)
  - `dp[i][w] = max(dp[i][w], dp[i-1][w - wt[i]] + val[i])` if `wt[i] <= w` (take item i)
- **Space optimization:** Traverse inner loop **right-to-left** when using 1D dp (prevents using item twice)

#### Unbounded Knapsack — Each Item Unlimited Times
Same as 0/1 knapsack but each item can be used any number of times.
- **Key difference:** When taking an item, stay at current item index instead of moving to previous (`dp[i][w-wt[i]]` not `dp[i-1][w-wt[i]]`)
- **1D space optimization:** Traverse inner loop **left-to-right** (allows reusing the same item)

#### Subset Sum Variants
- **"Can we form target?"** → boolean DP. `dp[w]` = true/false.
- **"Count subsets summing to target?"** → count DP. `dp[w]` += count.
- **Partition Equal Subset Sum:** Reduce to "can we form sum/2?" — 0/1 knapsack boolean variant.
- **Target Sum:** Count subsets with sum = `(total + target) / 2` — uses count variant.

#### LCS Patterns
- **Longest Common Subsequence (LCS):** `dp[i][j] = dp[i-1][j-1] + 1` if `s1[i] == s2[j]`, else `max(dp[i-1][j], dp[i][j-1])`
- **Derived problems — all reduce to LCS:**
  - Print LCS
  - Shortest Common Supersequence: `len(SCS) = len(s1) + len(s2) - LCS`
  - Min insertions/deletions to convert s1 to s2
  - **Longest Palindromic Subsequence (LPS):** `LPS(s) = LCS(s, reverse(s))`
  - Number of distinct subsequences

#### Matrix Chain Multiplication (MCM) Pattern — Interval DP
- **State:** `dp[i][j]` = optimal cost to solve the problem on the subarray/range `[i..j]`
- **Transition:** Try every split point `k` in `[i..j-1]`: `dp[i][j] = min over k of (dp[i][k] + dp[k+1][j] + cost(i, k, j))`
- **Base case:** `dp[i][i] = 0` (single element has no cost)
- **Traversal order:** Fill by increasing **length** of the interval
- **Problems using this pattern:** MCM itself, Burst Balloons, Palindrome Partitioning II, Optimal BST

#### DP on Stocks — State Machine Approach
Define **states** the portfolio can be in and **transitions** on each day:
- **At most 1 transaction (LC #121):** 2 states: holding, not-holding
- **Unlimited transactions (LC #122):** Same states, allow sell+rebuy
- **At most 2 transactions (LC #123):** 4 states: buy1, sell1, buy2, sell2
- **At most k transactions (LC #188):** 2k states or dp[k][day][holding]
- **With cooldown (LC #309):** Add a `cooldown` state after selling
- Study all variants sequentially — each builds on the previous.

#### LIS — Longest Increasing Subsequence
- **Naive DP:** `dp[i]` = LIS ending at index i. `dp[i] = max(dp[j]+1)` for all `j < i` where `nums[j] < nums[i]`. O(n²).
- **Optimized BS approach (Patience Sorting):** Maintain a `tails` array where `tails[i]` = smallest tail element for all IS of length `i+1`. Binary search to find where current element fits. O(n log n).

## Week 20–21: Tries + Advanced Graphs

### 🧠 Concepts to Master — Trie

#### Trie Data Structure
A tree where each **node represents a character** and each **root-to-node path represents a prefix**.

- **Node structure:** `TrieNode { TrieNode[26] children; boolean isEnd; }`
- In Java — `children` array of 26 is more cache-friendly than HashMap (but HashMap allows non-lowercase chars)
- **Insert (O(m) for word of length m):**
  - For each character, if `children[c-'a'] == null`: create new TrieNode
  - After last character: mark `isEnd = true`
- **Search (O(m)):**
  - For each character, if child is null → return false
  - At end: return `isEnd`
- **StartsWith (O(m)):**
  - Same as search but don't check `isEnd` — just check all characters exist
- **Space:** O(ALPHABET_SIZE × L × N) where L = average word length, N = number of words. Can be large.

#### When Trie Is the Right Choice
- Prefix-based operations (autocomplete, IP routing, spell check)
- Checking if any word in a dictionary is a prefix of another
- **Word Search II:** Multiple word search in a 2D grid — build a Trie from all words, then DFS the grid against the Trie. Avoids doing a full DFS per word.

#### Wildcard Search in Trie
When `'.'` can match any character (Design Add and Search Words):
- At a `.` node: recursively try ALL 26 children
- At a normal character: follow only that specific child

### 🧠 Concepts to Master — Advanced Graphs

#### Tarjan's Algorithm — Bridges and Articulation Points
Finds critical connections (bridges) in O(V + E) using a single DFS.

- **Discovery time (`disc[u]`):** The step at which node u was first visited during DFS
- **Low value (`low[u]`):** The minimum discovery time reachable from the subtree rooted at u via back edges
- **Bridge condition:** Edge `(u, v)` is a bridge if `low[v] > disc[u]`
  - This means: there is NO back edge from the subtree of v that reaches u or any ancestor of u. Removing this edge disconnects the graph.
- **Articulation point:** A node whose removal increases the number of connected components
- Must be studied from Striver's video series before attempting LC #1192

#### Strongly Connected Components (SCC) — Kosaraju's Algorithm
- **Step 1:** DFS on original graph. Push nodes to a stack in **finish order** (post-order)
- **Step 2:** Transpose (reverse all edges in) the graph
- **Step 3:** Pop from stack, DFS on transposed graph
- Each DFS tree in Step 3 = one Strongly Connected Component
- **Intuition:** In the transposed graph, you can't escape an SCC from the "deepest" node (highest finish time). So processing in reverse finish order gives each SCC exactly once.

## Week 22–23: Bit Manipulation + Intervals + Mixed Practice

### 🧠 Concepts to Master — Bit Manipulation

#### Core Bit Operations
| Operation | Java Syntax | Use Case |
|---|---|---|
| Check if bit i is set | `(n >> i) & 1` | Test specific bit position |
| Set bit i | `n \| (1 << i)` | Turn a specific bit on |
| Clear bit i | `n & ~(1 << i)` | Turn a specific bit off |
| Toggle bit i | `n ^ (1 << i)` | Flip a specific bit |
| Check power of 2 | `n > 0 && (n & (n-1)) == 0` | Exactly one bit set |
| Remove lowest set bit | `n & (n-1)` | Brian Kernighan's algorithm |
| Isolate lowest set bit | `n & (-n)` or `n & (~n+1)` | Get the rightmost 1-bit |
| XOR self-inverse | `x ^ x = 0` | Pairs cancel each other |
| XOR identity | `x ^ 0 = x` | No change |

#### XOR Properties — Critical for Interview Problems
- `a ^ a = 0` → any value XORed with itself = 0
- `a ^ 0 = a` → XOR with 0 is identity
- XOR is **commutative** (`a^b = b^a`) and **associative** (`(a^b)^c = a^(b^c)`)
- **Single Number:** XOR all elements in the array. All paired elements cancel (x^x=0). The unpaired element remains.
- **Finding two non-repeating elements:** XOR all → result is `a^b`. Find any set bit in result (use `result & (-result)`). Divide elements into two groups based on that bit. XOR each group separately.

#### Brian Kernighan's Algorithm — Count Set Bits
`n & (n-1)` removes the **rightmost set bit** of n. Repeat until n = 0.
```
count = 0
while n > 0:
    n = n & (n-1)    // remove lowest set bit
    count++
```
This is O(number of set bits) — better than O(32) for sparse numbers.

#### Bitmask DP — What It Is
- Represent a subset of n elements as an integer where bit `i` = whether element `i` is included
- With n elements, there are 2^n possible subsets → 2^n states
- **State:** `dp[mask]` where mask is a bitmask of visited/included elements
- **Iterate over all subsets:** `for mask in range(1 << n):`
- **Practical for n ≤ 20** (2^20 ≈ 1 million)
- **Use case:** Traveling Salesman Problem, assigning tasks to workers, covering all nodes in a graph

## 📐 Guiding Principles

1. **30-minute rule:** Spend at least 30 minutes genuinely attempting a problem before looking at the solution. Less than that = you're skipping growth. More than 60 min = look at a hint, not the full solution.
2. **Morning = Theory. Evening = Grind.** Theory absorbed on a fresh brain sticks. Evening problem-solving sharpens recall under fatigue — beneficial.
3. **Cooking time = free learning.** Queue ByteByteGo or Abdul Bari while cooking every day. That's ~5 hrs/week of passive absorption for zero extra effort.
4. **Contest is non-negotiable.** Never skip the weekly CodeChef contest. Pressure-based problem solving is a separate skill from calm practice.
5. **Post-contest review > the contest.** Reading editorials and implementing unsolved problems is the highest ROI activity in this entire plan.
6. **Sunday evenings: full rest.** Burnout ends 26-week plans. If you miss a day — continue next day, never double-up.
7. **Start applying by Week 17.** Real interviews expose blind spots 10× faster than any course. Don't wait for "100% ready."
8. **Your notification service is your superpower.** Practice narrating it as a system design case study. Start the story there in every SD interview.
